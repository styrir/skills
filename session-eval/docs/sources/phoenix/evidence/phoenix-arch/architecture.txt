Phoenix has two coupled planes. The ingestion/serving plane is OTLP HTTP/gRPC plus OpenInference normalization into a typed Span graph, database traces/project sessions, and FastAPI REST, GraphQL, UI, MCP, PXI, and CLI surfaces. The evaluation plane is either offline dataset→task run→evaluator result processing or online selector→settle/checkpoint→trace hydration→evaluator→annotation processing; datasets are versioned and experiments pin a version, with repetitions, trace IDs, errors, and CODE/LLM/HUMAN annotations. The separate Python OTEL/client/evals packages are intentionally split from the ELv2 server package, while the target Styrir skill should keep only independent local adapters/reporting/checks rather than running or vendoring this platform.
