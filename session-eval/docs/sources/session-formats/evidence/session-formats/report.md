## Observed implications for a first-party adapter

1. Implement five source adapters behind one bounded streaming interface. Primary streams are Claude project JSONL, Codex rollout JSONL, Pi JSONL, OMP JSONL (including children), and Grok chat/events/updates. Sidecars should enrich/index, not replace the source stream.
2. Make token accounting source-aware: Claude assistant usage is direct; Codex has both event and usage-record forms; Grok has usage.json, update metadata, and aggregate signals; Pi/OMP sampled files may have no stable per-session usage. Keep `unknown` distinct from zero.
3. Make skills a derived observation (`path`, `name`, `source`, confidence), not a required native event. Claude and Grok expose the strongest file-level evidence; Codex/Pi/OMP mostly expose textual/tool-argument references.
4. Preserve event provenance (`source_path`, line/ordinal, event id) and unknown fields so schema drift (especially Grok summary variants and Pi/OMP custom events) does not lose evidence.
5. Redact prompt content, tool arguments/results, encrypted blobs, system prompts, credential-pin values/hashes, and terminal output by default. Use bounded previews or hashes for HTML trend reports; never emit raw secrets.
6. Build reports from normalized aggregates plus bounded error/tool/skill observations. Reuse `workgraph-dossier`’s stable IDs and explicit malformed-event reporting patterns rather than copying full transcripts.

## proofGaps

- `~/.config/claude` was explicitly checked and is absent on this machine; only `~/.claude` was observed. No claim is made about another user, host, or future installation.
- The inventory sampled representative records and DB schemas rather than reading every transcript line. Full prompts, system prompts, terminal/tool outputs, and potentially sensitive context files were intentionally not dumped.
- Pi and OMP sampled transcripts did not expose a stable native per-session usage record. Their adapters should detect optional future usage metadata and report absent/unknown, not infer zero.
- OMP and Pi share the observed version-3 envelope shape, but compatibility across releases is not proven; retain version and unknown events.
- Grok summary storage has at least two observed key variants (`info` and older `session_info`); broader historical compatibility is not proven. Grok update timestamps and event timestamps use different observed representations.
- Codex SQLite schemas were inspected without dumping `item_json` rows; encrypted reasoning and large tool outputs may require retention/redaction policy decisions before a production ingest implementation.
- No generic parser exists locally for Codex, Pi, OMP, or Grok interactive sessions; the existing analyzer coverage is Claude dashboard plus WorkGraph evidence/dossier tooling.
- No web sources were consulted because all requested local paths were found except the explicitly missing `~/.config/claude` path.
