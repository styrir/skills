# Progress Events

Use progress events when a Styrir run may take more than one or two turns, especially `styrir_plus`, `deep_search_local`, or `nvidia_aiq_handoff` packaging. The goal is to keep the operator out of the dark without turning the search into a noisy transcript.

Append events to the run directory:

```bash
node --experimental-strip-types scripts/styrir-progress-event.ts <run-dir> <phase> "<message>" --mode <mode> [--budget-used n] [--budget-limit n] [--source-id s1]
```

The script writes one JSON object per line to `<run-dir>/progress.jsonl` and prints one compact line for chat or terminal surfacing.

## Event Fields

- `timestamp`: ISO timestamp generated by the script.
- `phase`: one of the legal phases below.
- `mode`: selected Styrir mode.
- `message`: concise operator-facing status.
- `budgetUsed`: optional current search/fetch budget count.
- `budgetLimit`: optional budget cap.
- `currentSourceId`: optional source id currently being fetched, read, or gated.

## Legal Phase Order

1. `routing`
2. `planning`
3. `searching`
4. `fetching`
5. `ledger`
6. `contradiction_sweep`
7. `gate`
8. `synthesis`
9. `handoff`

The helper allows skipped phases but blocks backward movement. It also blocks `gate` before a `ledger` event and `synthesis` before a `gate` event.

## Practical Pattern

- Emit `routing` once a mode and budget are selected.
- Emit `planning` when facets are chosen.
- Emit `searching` and `fetching` when a longer provider/source pass starts.
- Emit `ledger` when the evidence ledger is ready.
- Emit `contradiction_sweep` for Plus runs after the contradiction pass is written.
- Emit `gate` immediately before or after deterministic gate execution.
- Emit `synthesis` when drafting from a passing ledger.
- Emit `handoff` when packaging local deep-search or NVIDIA AI-Q manifests.

Keep messages short. Do not include secrets, API keys, full prompts, or large source excerpts in `progress.jsonl`.
