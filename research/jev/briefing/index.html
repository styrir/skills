Jev across our harnesses

Jev is TypeSafe's System One decision model: typed yes/no, pick-one, and scale answers in about 0.4 seconds for about $0.00003. This briefing covers where it cuts cost and time in Claude Code, Codex, Grok WorkGraph, and OMP; what we measured with our own Requesty key; what GPT-6 Astra's review changed; and what shipped.

live Jev calls ~400 model jev-1.13.0 via Requesty median latency ~430 ms total test spend ≈ $0.01 Astra verdict: SHIP-WITH-CHANGES

Bottom line

  1. A third primitive, not a cheaper LLM. Code handles numbers and thresholds, Jev handles bounded judgments, and agents handle open work. Jev writes nothing; it returns probabilities your code branches on.
  2. Usable today with keys we already hold. Requesty routes it as typesafe/jev-1.13.0, with the key from Infisical. No new vendor.
  3. The best returns come from keeping content out of frontier models, not from hooking every tool call. The priorities are scoping Plan briefs before the Opus consult, replacing the LLM fallback in workgraph-intent, answering questions about files without reading them, and swapping out JSON-parsing LLM classifiers.
  4. The hook guard works only with code rules as the boundary. On the first real run, an agent's harmless-looking … | sh; echo "exit=$?" slipped past our pipe-to-shell rule. We found it only because Astra insisted on testing real effects. It is now fixed and has regression coverage.
  5. Two skills shipped, both in observe mode by default: jev and jev-guard. WorkGraph work is filed in agent-ops as separate beads, with W2 and W1 first.

What Jev is

You send a state, which is text or JSON up to about 32k tokens, and a map of questions keyed by your own IDs. The IDs are never sent to the model. Each question is one of three types, and each answer is typed.

TypeYou askYou getUse it for
noulyes or no, with optional true/false criteriaP(yes)gates, flags, the smart if
choiceone of up to 255 options you definethe pick, every option's probability, confidence. It cannot invent a label.routing, classification
score2–10 ordered levels, low to higha fractional position, legend, probabilities, confidenceseverity, risk, grading

Price is $0.042 per million input tokens, and output is free. TypeSafe's own list of weak spots: literal reading, math and counting, dates, indirection, large irrelevant state, and adversarial text. Equivalent questions also don't give consistent numbers. Keep arithmetic in code, send only the state a question needs, and never carry a threshold across question types.

The hook, tested on real effects

Astra's main blocking finding was that classifier answers aren't hook behaviour. So we ran a headless Claude Code agent with Bash allowed, the guard enforced, and sentinel files on disk, then checked what actually happened. The first run failed. The second passed.

Why cheap reads compound

A file read into an agent's context is paid for again on every later request until compaction. Cached input is cheap per token but repeated many times. A Jev judgment about the same file is paid once, and the file never enters the window.

Placements

hold may only add friction. clear removes friction and needs stronger evidence. observe records only. route chooses a path before launch.

What Astra's review changed

This was one independent pass by GPT-6 Astra through the ask skill, with no back-and-forth. It gave 2 blocking and 11 major findings. Every factual claim it made was checked against the raw data before being accepted.

FindingDisposition
Blocking: a three-way classifier doesn't map onto hooks, and "prompt" doesn't mean execution pausedAccepted. Split into deny-only pretool and opt-in, family-scoped permission; added an end-to-end effect test, which found a real bug.
Blocking: the guard can leak what it protectsAccepted. Local redaction before every request, real-path containment, secret-like files refused, and a hash-only ledger. Approved-roots config is still open (skills-6z3.3).
"Every error went to prompt" was false; backups scored high; weekly cost was 5× lowAccepted and corrected above.
pi is 0.80.2, not 0.87.1Both are true: there are two installs, and PATH decides which runs. Flagged (skills-6z3.6).
W3 not implementable as written; W5 and W6 mis-characterizedAccepted. Rewritten per item.
Pinning was observation, not enforcementFixed. The client requests the pinned ID and errors on version drift.
Lead with instrumented W2, W1, and A1 pilots; add bounded Level 10Accepted. jev compose shipped.

Rollout

  1. This week, with no behaviour change. Link the two skills, store the Requesty key in Keychain (jev.requesty), install the guard's pretool, posttool, and prompt hooks in observe mode, and start using jev files and jev compose.
  2. Instrumented agent-ops pilots. Run the W2 brief-lint A/B, and W1 in shadow against the rules on every launch.
  3. Build the run-cost ledger (ops-1re.3) joining Claude, Grok, Codex, pipeline, and Jev usage, and report cost per accepted task. Nothing counts as savings until this exists.
  4. Enforce H1 after a clean week of ledger. Consider H2 only for a named test or read family, after measuring real prompt incidence.
  5. Later: an H3 behaviour test, the OMP adapter, Codex and Grok end-to-end runs, and W3 in shadow.
